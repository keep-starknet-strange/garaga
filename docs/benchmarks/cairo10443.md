# Cairo 2.21: PR #10443 measurements

Cairo 2.21.0 includes [PR #10443](https://github.com/starkware-libs/cairo/pull/10443), merged as `69c1ee15`.
It replaces the default four-limb guarantee destructor with `u96_limbs_less_than_guarantee_verify_v2`.

**This migration currently gets none of these savings.** Garaga retains the fully validated legacy checks because released Foundry and USC do not support the new instruction.

## Reproduce

Run this command from the repository root:

```sh
uv run --no-project venv/bin/python tools/benchmark_cairo10443.py \
  --iterations 1000 --output /tmp/cairo10443-results.json
```

The script requires Scarb 2.21.0 and verifies its version. It selects that version through `ASDF_SCARB_VERSION`.
It uses temporary sources and targets. It does not change the production compatibility API or installed tools.

## Method

The microbenchmark changes only the destructor in identical `get_output` helpers:

```cairo
// v1
guarantee.into_u96_guarantee().destruct();
// v2
guarantee.destruct();
```

Both helpers use core's `EvalCircuitTrait`, the same error type, and the same inline attribute.
The benchmarks use Cairo 2.21.0, Sierra 1.9.5, inlining strategy 2, and disabled gas calculation.
The native runner uses `--target standalone --output none`.
Each microbenchmark performs 1,000 checks and asserts every output. A zero-iteration run removes setup costs from the per-check counts.

The pairing benchmarks use the repository's existing valid fixtures.
Their isolated Garaga copies differ only in the output destructor; the failure validation and its result type remain unchanged.
Both variants assert successful proof checks. The script also asserts identical builtin counts.

## Results

### Microbenchmark

Limb 0 is the least significant limb. The higher limbs are equal before the indicated limb differs.

| First differing limb | v1 VM steps/check | v2 VM steps/check | Reduction |
| --- | ---: | ---: | ---: |
| 0 | 273 | 253 | 7.33% |
| 1 | 270 | 252 | 6.67% |
| 2 | 262 | 250 | 4.58% |
| 3 | 252 | 248 | 1.59% |

Both variants use 25 RangeCheck96 instances per iteration, including circuit inputs and evaluation.
Executable CASM shrinks from 2,542 to 2,491 felts (2.01%).
The library's Sierra statement count drops from 1,910 to 1,878 (1.68%).

### Pairing workloads

| Workload | v1 VM steps | v2 VM steps | Reduction |
| --- | ---: | ---: | ---: |
| BN254 2P/2F pairing check | 92,952 | 92,004 | 1.02% |
| Groth16 BN254 3P/2F pairing component | 117,740 | 115,148 | 2.20% |

For 2P/2F, CASM shrinks from 29,927 to 29,909 felts. Sierra drops from 19,340 to 19,313 statements.
For 3P/2F, CASM shrinks from 39,356 to 39,275 felts. Sierra drops from 24,833 to 24,764 statements.

Memory holes drop from 7,431 to 6,720 for 2P/2F, and from 10,310 to 8,366 for 3P/2F.
These are separate memory metrics, not additional VM steps. Builtin counts remain identical for each A/B pair.

## Scope and provenance

These measurements show native VM resource reductions, not transaction fee savings.
Gas calculation is disabled. Wall-clock timings were noisy during concurrent CI profiling, so this report makes no elapsed-time claim.
The 3P/2F workload covers the Groth16 pairing component, not the full verifier.
The native executable runner rejects the full SP1 verifier's `sha256_process_block_syscall`.

Replacing both Garaga traits with core traits changes the error-result layout as well as the destructor.
That comparison does not isolate this upstream change and is excluded from these results.

The [raw results](cairo10443-results.json) contain setup counts, builtin counts, memory metrics, compiler versions, and source hashes.
The run used Scarb `2.21.0 (fbd5bd03d)`, Cairo `2.21.0`, and native runner `execute 2.21.0` on `aarch64-apple-darwin`.
