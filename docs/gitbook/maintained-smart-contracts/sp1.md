# SP1

Garaga verifies SHA-256 SP1 Groth16 receipts on Starknet with the v6.1.0 circuit.
The integration is tested against the official `sp1-verifier` crate from SDK 6.10.0.
SDK and circuit versions are separate: SDK 6.10.0 still uses the v6.1.0 circuit.

## Proof format

The proof JSON contains `vkey`, `publicValues`, and `proof` as hexadecimal strings.
The program verification-key hash is 32 bytes.
The Cairo interfaces require `publicValues` to contain complete 32-byte words.
This alignment requirement also applies to the Python, Rust, and TypeScript parsers.
Blake3 public-value commitments are not supported by this Cairo verifier.

The encoded proof is exactly 356 bytes:

| Bytes | Content |
| --- | --- |
| 0–3 | Verifier selector `4388a21c` |
| 4–35 | Exit code, which must be zero |
| 36–67 | Recursion verification-key root |
| 68–99 | Proof nonce |
| 100–355 | Groth16 proof points |

The five Groth16 inputs are the program key, masked SHA-256 public-value digest, exit code, recursion root, and nonce.
Garaga verifies the expected recursion root and canonical scalar encodings before the pairing check.
The nonce participates in the pairing equation; changing it invalidates the proof.
Old v5 receipts and calldata are incompatible with this verifier.
Declare the regenerated verifier before using v6 receipts in an application.

## Update the integration

`tools/make/constants.json` defines the tested SDK version, circuit version, verifier hash, and expected recursion root.
The shared examples directory contains `vk_sp1.json` and `proof_sp1.json`.
`sp1_artifacts.json` records their source revisions and proof fingerprints.
The fixture was produced with SDK 6.1.0 and is independently verified with SDK 6.10.0 in the Rust tests.

1. Select the SDK and its circuit version from the official SP1 release.
2. Update the SP1 section in `tools/make/constants.json`.
3. Replace `vk_sp1.json` with the matching Groth16 key.
4. Replace `proof_sp1.json` with a valid SHA-256 receipt and update its provenance.
5. Run these commands from the repository root after environment setup:

```bash
make constants
cargo update --manifest-path tools/sp1_verifier/Cargo.toml -p sp1-verifier
make maturin
make rewrite
python tests/hydra/starknet/test_groth16_vk_proof_parsing.py --update-golden
make wasm
pytest tests/configuration/test_sp1_release.py
CARGO_TARGET_DIR=.cargo/sp1_verifier/target cargo test --locked --manifest-path tools/sp1_verifier/Cargo.toml
(cd src/contracts/autogenerated/sp1_verifier_bn254 && snforge test)
```

`make constants` updates all three language constants, the Rust verification key, and the SDK test dependency.
`make rewrite` regenerates the Cairo key, contract, negative tests, and both stored calldata files.
It converts the committed receipt to calldata without running a prover.
Generate a new proof only when the circuit changes or another fixture is required.

## Automatic verification

A dedicated SP1 CI job verifies the stored receipt with the actual official verifier and with Garaga.
Its isolated Rust workspace is `tools/sp1_verifier`; the SDK is a test dependency there.
They compare the SDK verification-key fingerprint and recursion root with the generated defaults.
The Python tests verify release consistency, Python/Rust calldata parity, and both stored Cairo calldata files.
TypeScript/WASM and all four npm integration consumers compare calldata against the same Python reference vector.
Cairo tests verify the proof through both the library and generated contract.
They also reject invalid exit codes, roots, and nonce encodings, and detect a changed nonce.
Devnet CI verifies the generated contract after deployment.
CI verifies stored proofs; it never generates SP1 proofs.
